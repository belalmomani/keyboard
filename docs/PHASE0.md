# Terminal AR — تقرير المرحلة 0 (الفحص والتخطيط)

## 1. حالة المستودع والبيئة
- المستودع: جديد/فارغ من جهتي (المستخدم يرفع الملفات بنفسه إلى GitHub).
- بيئة العمل عندي: Rust 1.97 وNode 22 وPython 3.13 موجودة، لكن **الوصول إلى crates.io وnpm محجوب**، فلا أستطيع تثبيت الاعتماديات ولا بناء المشروع ولا توليد ملفات القفل (Cargo.lock / package-lock.json) هنا.
- النتيجة: كل بناء واختبار فعلي يتم على GitHub Actions، وليس عندي.

## 2. التقنيات والإصدارات
| التقنية | ما تحققت منه | الحالة |
|---|---|---|
| Runner: windows-latest | Windows Server 2025، Node 22.x و24.x، Visual Studio 2026 (صورة 20260628) | مؤكد |
| portable-pty (يدعم ConPTY على Windows) | الإصدار 0.9.0 ظهر في docs.rs | مؤكد جزئياً |
| @xterm/xterm | الإصدار 6.0.0 موجود | مؤكد جزئياً (قد يوجد أحدث) |
| Tauri 2 | لم أستطع قراءة رقم الإصدار الحالي | غير مؤكد |
| Rust على الـ runner | غير مذكور في ملاحظات الصورة | يُتحقق منه في Actions |
| WebView2 / NSIS / WiX | غير مذكور | يُتحقق منه في أول بناء |

القرار المقترح: تثبيت الإصدارات الدقيقة بعد أول بناء ناجح على Actions، وتخزين ملفات القفل في المستودع.

## 3. المخاطر التقنية
1. لا أستطيع تشغيل الكود عندي، فتظهر أخطاء الترجمة أولاً في Actions وتحتاج دورات إصلاح.
2. ConPTY يعمل على Windows فقط، فاختباره يتم على runner ويحتاج اختبارات تكامل آلية.
3. اختبار الواجهة تفاعلياً يتطلب جهاز Windows بيد المستخدم.
4. عزل الأدوات (AppContainer وغيره) معقد، وسيُبحث في المرحلة 4 ولا يُدّعى الأمان قبل إثباته.
5. Relay يتطلب خادماً فعلياً وتكلفة، ولن يُبنى قبل تقرير التكلفة.
6. التوقيع: Windows يحتاج شهادة توقيع كود، والنسخ الأولى ستكون غير موقعة وسيظهر تحذير SmartScreen.

## 4. معايير القبول
- المرحلة 1: اختبارات الطرفية الثمانية في القسم 26 تعمل آلياً على windows-latest، ويُنتج مثبّت قابل للتنزيل من Artifacts برقم بناء ظاهر.
- باقي المراحل: تُحدَّد معايير كل مرحلة قبل بدئها وتُعرض عليك للموافقة.

## 5. قرارات تحتاج موافقتك
1. ملفات القفل: تُولَّد في أول تشغيل على Actions وتُنزَّل لتضيفها للمستودع.
2. هل لديك جهاز Windows لتجربة المثبّت؟
3. الجزء المقطوع من القسم 26 (من البند 8) لم يصلني.
